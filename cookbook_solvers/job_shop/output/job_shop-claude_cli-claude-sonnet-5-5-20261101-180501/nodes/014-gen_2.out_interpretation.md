**Optimal makespan: 8 time units.** All three jobs finish by time 8, and the solver proved no schedule can do better. It matches the known optimum.

**Bottleneck: M1.** It has 8 units of work (3 + 3 + 2) and is busy from 0 to 8 with no gaps. M2 and M3 each have only 5 units of work. Since M1 can't finish its work in fewer than 8 units, 8 is the floor for any schedule, which is why this one is optimal.

**Schedule in plain language**
- **Job1** runs straight through with no delays: M1 (0-3), M2 (3-5), M3 (5-7). It finishes at 7.
- **Job2** starts on M2 (0-2), then waits for M1, runs on M1 (3-6), waits again, and finishes on M3 (7-8).
- **Job3** starts on M3 (0-2), moves to M2 (2-3), waits for M1, then runs on M1 (6-8).

**Waiting time**
- Job2 waits 1 unit (2→3) for M1, which Job1 is using, and 1 unit (6→7) for M3, which Job1 is using.
- Job3 waits 3 units (3→6) for M1, which is occupied by Job1 and then Job2.
- Job1 never waits.
- All of this waiting comes from jobs queuing for M1. Meanwhile M2 sits idle from 5 to 8 and M3 from 2 to 5, so the other machines have spare time that can't be used to speed things up.

**Takeaway:** Total time is set by the busiest machine (M1), so to finish sooner you'd need to speed up or add capacity on M1; rearranging the other machines won't help.
