## What this is

GraphLang: a graph-first language for agentic workflows. The graph (YAML, `*.graph.yaml`) is the program; the LLM mutates topology instead of writing code. It evolves from the sibling repo SPL.py (`spl3` package). Early prototype; much of the code was drafted by Qwen and then adopted/fixed piecemeal. `README.md` is aspirational (some claims, e.g. Rust compilation and Cedar enforcement, are not implemented yet).

## Commands

```bash
pip install -e ".[dev]"                      # extras: dev, anthropic/gemini (provider SDKs via dd-llm; the openai SDK is core), spl (procedure_ref only), kernel (`backend: kernel` on SOLVE: jupyter_client, ipykernel), grafc (jinja2)
pytest                                       # all tests (use the `graf` conda env's python: it has zinet, dd-llm, SPL.py)
pytest tests/test_grafr_loop.py::test_name   # single test
pytest --mode llm                           # only the few real-LLM tests (claude_cli, claude-sonnet-5-5); plain `pytest` is offline only; `-m` is refused (see tests/README.md); `--mode all` runs both
graf run cookbook/self_refine/self_refine.graph.yaml --param key=value   # adapter defaults to `claude_cli` with claude-sonnet-5-5 (a real LLM, billed; give a `--bind` file with `limits.max_llm_calls` when trying a loop); --param is repeatable
graf validate|info <graph.yaml>
graf describe <graph.yaml|recipe-folder> [-o FILE|-] [--force] [--llm [ADAPTER:MODEL]]   # writes RECIPE.spec.md in the folder (FILE.spec.md beside a graph file; `-o -` prints; an existing default needs --force); the graph in words (inputs, output, steps in order with prompts and function names, data flow, cost; grafc/describe.py), from the file alone, no model; with --llm one billed call writes a specification from the structure plus the folder's readme/prompts/procedures/tools/policies; the text is what `graf create --spec @FILE` takes (round trip graph -> specification -> graph)
graf docs SOURCE [--style demo,tutorial,user-guide,custom (comma list)] [--prompt TEXT|@FILE] [--format html|markdown] [--out-dir DIR | --out FILE] [--ref BRANCH] [--llm ..] [--max-calls N] [--dry-run]   # SOURCE is a folder or a repo url (shallow-cloned to /tmp/graflang-docs); writes <out-dir or .>/<name>.<style>.html|md, one file per style (Markdown styles are converted by grafd/md2html.py unless --format markdown); runs cookbook/doc_it (gather program -> outline, write -> assemble+check program -> fix once), the styles are files in graphlang/grafd/styles/*.md (demo also has demo.template.html, the deck's page); the cap on model calls comes from the graph + 50%
graf run ... --log-level debug --log-format jsonl|text|both --log-dir DIR --no-log --output-dir DIR --no-save-nodes --no-output   # logs default to ~/.graflang/logs
graf create --name N --spec TEXT|@FILE [--out-dir DIR] [--llm adapter:model] [--max-rounds 3] [--allow-code] [--from RECIPE|--no-examples] [--embedding SPEC]   # similar recipes from the work area go into the prompt (`find_examples`, shared with the app's Create page); vibe-coding: an LLM writes a graph app (grafc/create.py + create_guide.md + create_examples/), checked like validate plus a mock dry run; the shipped examples are validated by tests/test_create.py
graf compile <graph.yaml> [--lang rust|spl|pocketflow] [-o OUT] [--dry-run]   # spl: SPL script (graf export-spl is folded in); pocketflow: a standalone PocketFlow program for a line/branch/retry-wire graph (GENERATE, SOLVE expression, EVALUATE, ASSERT; refuses the rest, grafe/graph2pocketflow.py); rust: experimental stub; both run `validate`'s checks first
graf compact <graph.yaml> [-o FILE]   # long form -> steps:, verified by expanding again (grafr/compactify.py)
graf trace [LOG] [--format tree|otlp] [-o FILE]   # a run's .jsonl log as a timeline or OpenTelemetry spans (grafr/trace.py)
graf watch <graph.yaml> [--every S] [--times N] [graf run options]   # run it on a schedule, one process per run; `graf run --stream` prints each node as it finishes
graf vis <graph.yaml> [--engine cytoscape|graphviz|pyvis|graphify|mermaid] [-o FILE] [--no-open]   # draw the workflow (default ~/.graflang/vis/); `python -m graphlang ...` also works
```

`graf` is one `click` group (`main` in `graphlang/cli.py`); each command lives in its package (`grafr/cli.py`: run/validate/info, `grafc/cli.py`: compile/check, `grafv/cli.py`: vis) as a plain `@click.command("name")` and is registered in `graphlang/cli.py`. There are no `grafr`/`grafc` console scripts. Imports in tests must be `graphlang.grafr...` / `graphlang.grafc...`. Tests under `tests/test_cedar_compiler.py` and `test_policy_slicer.py` exercise the hand-written Cedar compiler and have known failures (gap #18).

Real LLM calls: `--llm claude_cli:<model-id>` (same as `--adapter claude_cli --model <id>`; `--llm` wins) goes through dd-llm (`/home/gongai/projects/digital-duck/dd-llm`, a core dependency; `pip install -e` it if missing). `procedure_ref` nodes additionally need SPL.py importable (`pip install -e /path/to/SPL.py` or set `SPL_PY_PATH`). The `mock` adapter (kept for the test suite, not documented for users) needs no LLM; tests use it or stub models.

## Architecture

- `graphlang/schema/`: `graflang-ir.json` (node/edge schema, validated by the runtime; a missing schema is an error, not a silent skip) and `graph_delta.schema.json` (MUTATE delta, enforced by `MUTATE`).
- `graphlang/grafr/`: the dynamic interpreter.
  - `runtime.py` loads YAML into a `networkx.MultiDiGraph` and executes it as **token-passing dataflow** (not true interaction-net rewriting, gap #26). Two edge types: `triggers` (control tokens between ports like `complete`/`pass`/`fail`) and `binds` (data, keyed by port name; last writer wins). Nodes may re-fire (retry wires work), `JOIN` is a barrier, `FORK` emits on all control ports, `--max-steps` bounds runaway loops (`RunLimitExceeded`).
  - `nodes/`: one executor per node type (GENERATE, EVALUATE, SOLVE, ASSERT, LOOP, GUARD, MUTATE, CONTEXT...), registered via `register_executor` in `nodes/__init__.py`. `LOOP` runs its `subgraph` once per iteration, with condition checked before each iteration.
  - `expr.py`: safe expression evaluator for `@var` conditions (no `eval`; whitelisted functions). Use it for any new condition syntax.
  - `adapters.py`: `mock` plus dd-llm adapters. `resolver.py`: resolves the `resources` block (procedures/prompts/policies, three-tier composition).
  - `cedar_guard.py`: Cedar checks for GUARD/MUTATE via the official engine (`cedarpy`), fail-closed (any evaluation error denies); callers must pass every attribute the policies read. `run_code.py` is `RUN_CODE` (run a step's program text, risky, never fails the graph); `decision.py` is `DECISION` (a person as a node: terminal, `--answer`, `default`; interactive only; a delta cannot touch it); `run_node.py` is `RUN` (executors subprocess, python, http); `outside.py` is `QUERY` (read a file, confined to the graph's folder), `EMIT` (file, stdout, webhook, e-mail; a dry run under the `mock` adapter only reports) and `OBSERVE` (log and `observations.jsonl`, never fails a run), with their `graf validate` checks; `QUERY` and `EMIT` are risky (behind a GUARD) and their path/target keys are `CODE_KEYS`; `BATCH` and the opt-in concurrent mode (`workers`, `_drain_waves`) live in `runtime.py`. `lifecycle.py` wraps every node in `pre -> exec -> post` when it has `config.phases` (timeout, retry, fallback, `out_schema`, routing on the result); `RECOVER` (`nodes/recover.py`) is the node an `error` route ends in. `ports.py` holds typed ports (a node's `ports` may be a name-to-type mapping; `load_graph` and the runtime normalize it to the name list plus `port_types`). `topology.py` backs `graf validate`. `procedures.py` runs a node's `procedure_ref` SPL workflow through SPL.py's executor. `MUTATE` validates (schema, structure, safety layer, Cedar, budget, then `topology.invariants` on a trial copy: guarded risky nodes, no race, no JOIN deadlock) and applies deltas; a delta can never remove or edit a `GUARD`/`MUTATE` node or the `risky` flag; the written rules are in `docs/DEV/DESIGN/graflang-semantics.md` (pinned by `tests/test_semantics.py`); a MUTATE inside a LOOP body affects only that iteration's copy (gap #32). `SOLVE` computes through `expression`, `procedure_ref`, or a `backend`: `kernel` (a Python kernel, `kernel.py`) or `subprocess` (a black-box program read through a declared parser, `solver.py`), both run by `solve_backend.py`, which also holds their `graf validate` checks; a `subprocess` node may add `container: {image, ...}` (`docker run`, no network, read-only; `solver.container_command`; under Docker Desktop a mount outside $HOME hangs, so `check_mount_shared` refuses it; tested with a stub `docker` and, when a daemon and `python:3.12-slim` exist, for real; `cookbook/container_demo`). A SOLVE with none of the three is an error (gap #31, closed). A MUTATE delta may never add or change `backend`, `code`, `result`, `command`, `parse` or `env_passthrough`, and the `QUERY`/`EMIT` keys `file`, `channel`, `recipients`, `sender`, `smtp_host`, `smtp_port`, `allow_dirs` (`CODE_KEYS`): refused before any policy runs, nested values included.
- `graphlang/grafc/`: the compiler, mostly a stub. `cedar/` is a ~1,500-line hand-written Cedar lexer/parser/type checker/compiler (open decision: keep, or use the official `cedar-policy` crate); `rust_gen/` is Rust codegen; also analyzer/optimizer/visualizer.
- Logging: dd-logging (`/home/gongai/projects/digital-duck/dd-logging`, a core dependency; `pip install -e` it if missing) via `graphlang/logging_config.py`. Use `get_logger("grafr.<module>")` and `log_event(_log, "noun.verb", **fields)` (fields land as JSONL keys); never `logging.getLogger` or `print` for run diagnostics. Nothing is logged until `setup_logging` is called (the CLI does).
- Independence from SPL.py: graflang does not depend on it, except `procedure_ref` (optional, lazy import: runs a `.spl` workflow, as `cookbook/code_pipeline` does) and, planned, emitting `.spl`. `spl2graph` lives in SPL.py and only writes this repo's graph format; `cookbook/chain_of_thought` and `cookbook/lifted_tool` are graphs it lifted (a Python tool becomes a `kernel` SOLVE that carries its own source).
- `graphlang/grafe/`: `graf compile --lang spl` writes a graph as `.spl` text (`graph2spl.py`); it never imports SPL.py. `graph2pocketflow.py` writes a PocketFlow program (template, no model; its OUTPUT classes carry `boundary = True` for tools that read the flow). `grafr/compact.py` is the `steps:` form (expanded in `load_graph`; `graf expand`; `compactify.py` is the inverse, `graf compact`: each result is re-expanded and compared with the input, a node that does not come back stays in `nodes:`/`edges:`), `grafr/bindings.py` the `--bind` file. `grafr/parts.py` expands named subgraphs: a workflow file (one INPUT, one or more OUTPUT nodes; a QUERY/EMIT `file` in a part is anchored to the part's folder at expansion) listed under `resources.parts` and used as a `SUBGRAPH` node (compact `use`) is flattened in place by `load_graph`, the runtime and `topology.check` (ids `<use>__<node>`, the part's prompts/procedures/policies joined to the parent's resources); the runtime has no SUBGRAPH semantics. Parts may be named (`cookbook:name[@hash]`, `parts.named_part`), carry `description`/`schema` on their inputs/outputs, and are held to the using graph's `workflow.parts_policy` (`grafr/partinfo.py`: capabilities, cost, `graf parts`); a MUTATE `add_part` delta adds a recipe from the node's `catalogue` at run time (`runtime._expand_added_part`). `grafr/expand.py` is the `expand:` block (first named `elaborate:`, still read) (a part applied to every node of a graph of things; edges become FORK/JOIN wiring), expanded first by `flatten_parts`; LOOP `persist_mutations: true` carries a MUTATE's changes to the next iteration.
- `graphlang/grafv/editor.py` + `app.py` + `pages/`: `graf vis --edit` (alias `graf ui`), a Streamlit app of six page files in `pages/` (`00-welcome.py`, `01-create.py`, `02-edit.py`, `04-browse.py`, `80-transfer.py`, `99-settings.py`; the number orders them; `app.py` is only the navigation). `GraphEditor` edits a long-form file through ruamel (comments kept), validates before saving; `chat_ops.py` turns a model's JSON operations into `GraphEditor` calls (all or none; prompt files staged until Save); `ui.py` holds the shared settings/LLM/picture helpers; `graphlang/workspace.py` is the work area (`~/.graflang/cookbook` and `solvers` read-only + `apps`, or `--src-dir`), zip import/export and the settings file (API keys, mode 0600). Create uses `grafc/create.py` (`create_app`, `revise_app`) and `graphlang/recipe_index.py` + `embedding.py` (recipe search: meaning via dd-embed plus BM25, one entry per recipe; Browse page; similar recipes go into the Create prompt as examples; tests set `embedding: none` so plain pytest is offline). Tests: `tests/test_editor*.py`, `test_app_pages.py`, `test_workspace.py`, `test_chat_ops.py` (the page tests skip without Streamlit).
- `graphlang/grafv/`: `graf vis`. `model.py` turns a workflow YAML into a `networkx` graph (LOOP bodies become `parent` nodes, ids `<loop>/<node>`); `engines.py` is only a `Style` (`graphlang_style`: colour by node type, `binds` edges dashed, a LOOP as a box) and a `render` wrapper: the engines themselves (cytoscape, graphviz, mermaid, ascii, and pyvis / graphify with the `vis` / `graphify` extras) live in the sibling **zinet** library (`zinet.vis`), shared with work-graph. To change how a graph is drawn, change the engine in zinet; to change what a workflow looks like, change the style here. `formats.py` reuses `zinet.formats` to recognise other graph files.
- `graphlang/policies/`: shared Cedar policies (`graph_safety.cedar`, `mutation_safety.cedar`), referenced from graph YAMLs via `resources.policies`.
- `cookbook/`: example graphs (`code_pipeline`, `self_refine`, `your_book`, `compliance_audit`, `solver_check`: both SOLVE backends, no LLM; `ts_verify`: an LLM writes TypeScript, Node and tsc judge it, needs Node 22.18+) with their `prompts/`. `code_pipeline` has its `.spl` procedures (`00`-`07`) next to the graph; running them for real needs SPL.py importable.
- `experiments/code_pipeline/`: shared experiment running the `code_pipeline` workflow through four arms (`single`, `spl`, `graflang`, `langgraph`) on HumanEval tasks, scored by one hidden-test oracle (`run.py`, `run_full.sh`, `analyze.py`; see its README). The arms must be held equal (same prompts, model, gates); don't change a workflow for one arm only. Tested by `tests/test_experiment_*.py`.
- `docs/`: `GUIDE/` (SETUP, TUTORIAL, USER-GUIDE, contributor-guide) and `DEV/` (design notes).

## Conventions

- Vocabulary is deliberately settled by the owner: node types `FORK`/`JOIN` (short names, no implicit fan-out), port exclusion rather than Pauli-exclusion wording. Don't reintroduce Qwen's superposition/entanglement/conservation language.
- Do not reuse unsupported claims from the Qwen draft paper (e.g. "40% fewer loops", "2x faster audits"); no experiments exist.
- File names: a semantic infix plus an existing format extension (`NAME.graph.yaml`, `NAME.spec.md`), not a new extension. The infix says what the file means, the extension says how to open it. Use this for any new kind of file.
- Treat Qwen-originated files as unreviewed drafts; verify behaviour with tests before building on them.
