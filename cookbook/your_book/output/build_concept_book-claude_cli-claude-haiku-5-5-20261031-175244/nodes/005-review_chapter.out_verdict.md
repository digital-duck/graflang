REVISION_NEEDED
1. **Garbled sentence in section 7.** The last sentence of the repeated-sampling discussion reads "Systematic errors make extra samples expensive agreement with the wrong answer." It is missing a verb or punctuation. Rewrite it so it says that extra samples become expensive agreement with a wrong answer.
2. **Imprecise independence and accuracy condition in section 7.** "The per-sample accuracy must be above chance" blurs two conditions. Majority voting needs, for each input x, a per-input success probability p_x > 1/2 (for binary decisions), and samples that are conditionally independent given x. Average accuracy across inputs can look fine while many individual p_x fall below 1/2. State the conditions per input and tie the systematic-error example to that.
3. **Inconsistent structured-output guarantee.** Section 1 uses reject-and-retry, and question 1 assumes the stage "guarantees" valid JSON. The chapter never says how that guarantee is obtained. Add the mechanism and compare the competing approaches: grammar-constrained decoding guarantees syntax but not semantics and can alter the output distribution; parse-and-retry is simpler but adds latency and can still fail after the retry budget is spent. Question 1 should name which mechanism it assumes.
4. **Aleatoric/epistemic section overstates what sampling shows.** "Sampling many outputs will show it [aleatoric uncertainty]" conflates the model's sample dispersion with the task's intrinsic ambiguity. A miscalibrated model can be consistent on an ambiguous input, and a high-variance sample does not prove the input is ambiguous. Add that the decomposition is contested for LLMs and that no standard estimator separates the two from samples alone.
5. **Informal claims about calibration without conditions.** "Models trained to produce fluent, helpful text tend to sound confident" and "absolute values often do not match observed accuracy" need qualifiers: calibration depends on tuning, prompt, task and domain. Describe the line of work on verbalised versus token-probability confidence, and state the limits of each, without citing specific papers.
6. **Task-level reliability is not defined formally.** Define it as an expectation over the input distribution, for example E_x[P(system output is correct | x)], and state that it depends on that distribution. This also ties to the representativeness condition in section 6.
7. **Style: concrete examples are missing in several sections.** Sections 4 (calibration), 6 (evaluation design) and 8 (evidence quality) have no worked example, and sections 2, 6 and 8 read more formally than "clear and conversational." Add one concrete example to each. For section 8, a useful one: with 500 test items and accuracy near 0.8, the sampling standard error over items is about sqrt(0.8·0.2/500) ≈ 1.8 points, so a two-point gain on one run is within noise. Name this as item-sampling error, which is separate from run-to-run variance.
8. **Minor: section 2 omits non-determinism at temperature 0.** Hosted APIs can still vary at temperature 0 because of batching and hardware. Note this, since it bears on the "same prompt, different output" framing.
9. **Minor: question 3's target.** The binomial calculation for 9 votes at 75% per-call accuracy gives about 95% under independence, not "roughly 90%". Either state the 95% figure or ask what error correlation would drop it to 90%.
